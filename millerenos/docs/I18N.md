# Internationalization

- Locales: `en` (LTR), `fa` (RTL). Add a locale by adding catalogs in `apps/server/src/i18n/`, `apps/miniapp/src/i18n.ts`,
  `web/content.ts`, and the `CHECK (locale IN …)` constraint via a migration. A unit test fails if catalogs have
  different keys or placeholders.
- No hard-coded UI strings in bot, Mini App or site — all text goes through `t(key, vars)`.
- Direction: `<html lang dir>` set per locale; CSS uses logical properties (`inset-inline-start`, `padding-inline-*`).
- Numbers/dates/money: `Intl` with `fa-IR` / `en-US`; Persian digits in the Mini App; input parsing accepts Persian and
  Arabic-Indic digits (`parseAmount`).
- Locale detection: Telegram `language_code` is only a first guess; the user chooses explicitly at `/start` and can
  change it in the bot or the Mini App. The site never auto-redirects by IP or header.
- Translations are reviewed by a human before publishing. Do not machine-publish translated pages at scale.
- Future locales (de, tr, ar): add catalogs + `/de/` paths; sitemaps and hreflang pick them up from `LOCALES`.
